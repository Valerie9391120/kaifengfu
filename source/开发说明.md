# 开发说明

写给以后接着改开封府的人（多半是我自己）。

## 先读这条

这个仓库是**公开的**。名帖、信、聊天、日记、照片、暗号、各种 key，一样都不许进仓库，测试里也只用编的假数据。私人内容只存在她手机上，加密后同步到 Supabase。

## 改前端

```
cd source
npm install
pip install playwright pillow                    # 测试用；浏览器用机器上装好的 Chrome
# 改 src/ 里的代码
npm run test:unit                                # 同步引擎、液态玻璃滑块、昵称、Word 取字、文档、通知、替她等回话，各一份
npm run build:test
npm run mock &                                   # 假 Supabase，端口 8787（通知的小后端在里面跑的是真的那一份）
(cd dist-test && python3 -m http.server 8080 &)  # 测试网页，端口 8080
npm run test:e2e                                 # 真浏览器走一遍完整流程（tests/e2e.py）、通知（tests/e2e_push.py）、替她等回话（tests/e2e_mail.py）和它的边角情形（tests/e2e_mail_edge.py）
KFS_OLD_PATH=1 python3 tests/e2e.py              # 同一套流程，装作信箱没建，整套走老路：两条路都得过
python3 tests/fullscreen.py                      # 主屏幕底下空一条：撑满、贴底淡出、几种情况
npm run build                                    # 正式包，在 dist/
```

把 `dist/` 里的东西复制到仓库根目录（先把根目录里旧的 `assets/`、`icons/`、`icons-dingxiang/`、`dingxiang/`、`index.html`、`sw.js`、两个 `manifest*.webmanifest` 删掉），连同改过的 `source/` 一起提交推送。GitHub Pages 几分钟后更新，她把 app 从后台彻底划掉再打开就能看到。

## 改后端

两个函数（`claude`、`push`）和数据库不在 GitHub 上运行，改了以后要她在 Supabase 网页上贴进去：

- 函数：Edge Functions → `claude`（或 `push`）→ 换成新代码 → Deploy。两个函数别的设置要一样（都是函数自己认人）
- 数据库：SQL Editor → 运行新的 SQL（`database.sql` 是库房，`push.sql` 是通知的登记簿，`mailbox.sql` 是信箱）
- 密钥柜：Edge Functions → Secrets（`ANTHROPIC_API_KEY`、`ALLOWED_EMAIL`，两个函数共用；通知另有三样 `VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`、`VAPID_SUBJECT`，在账户面板的“通知”里生成，见下面“通知”那节；网页哪天搬了家，再加一样 `ALLOWED_ORIGIN` 写新地址，不然点了通知回不来；**只写到域名**，像 `https://xxx.github.io`，后面不带斜杠和路径，见“第二步”里“点了横幅只回开封府自己的地址”）

密钥柜里的值改了不用重新 Deploy，函数下一次被叫到就读新的。

Anthropic 的 key：在 Claude Console 的 Settings → API keys → Create key 新建。新版 Console 的 key 分“绑定一个工作区”和“能用好几个工作区”两种，后一种每次请求都得带 `anthropic-workspace-id` 头，否则报 “This API key is not scoped to a workspace”。我们的函数不带这个头，所以建 key 时一定要选一个工作区；过期时间选“永不过期”，不然到期那天开封府就哑了。

## 要她重新添加到主屏幕的改动

`index.html` 里 `apple-mobile-web-app-*` 开头的设置、主屏幕图标、App 名字：iOS 在添加到主屏幕时读，改了要删掉图标重新添加。

删图标会把这个主屏幕 App 在手机上的存档一起删掉（每个主屏幕 App 有自己的一份）。删之前：账户面板里要写着“都已同步”；最好再导出一份备份；她得记得邮箱、密码和暗号。重新添加以后登录、对暗号，云端的东西会全部回来。

换图标：替换 `static/icon-source.jpg`，在 `source/` 里跑 `python3 tools/make_icons.py`，再打包。图标网址后面带着内容的指纹（`?v=…`），Safari 添加时不会拿缓存里的旧图。

## 主题和入口

两个主题：青绿（沙燕）和丁香（小猪）。

- **颜色**全写成 CSS 变量：`input.css` 里 `:root` 是青绿，`html[data-kfs-theme="dingxiang"]` 是丁香。变量是“红,绿,蓝”三个数（`--k-ink`、`--k-soft`、`--k-dai`、`--k-shade`、`--k-base`、`--k-motto` 这些），代码里写 `rgb(var(--k-ink))`、`rgba(var(--k-soft),0.5)`。换主题只换 `<html>` 上的 `data-kfs-theme`，页面不用重画。新加颜色别写死青绿的数，用变量。SVG 的 `stroke` 属性里不认 `var()`，图标的颜色走 `style`（见 `Icon`）。
- **图**跟着 `useTheme()` 换：聊天背景（`THEMES[theme].wall`）、开屏（`SplashByTheme`）。青绿的开屏是戳燕子；丁香的开屏（`SplashDingxiang.jsx`）是小猪，过半秒底下浮出滑块，圆钮拉到最右边小猪脸红、白心里长出小紫心（两小块透明图叠上去，位置在 `SPLASH_DX` 里），松手才进门。滑块是液态玻璃，见下面那节。
- **记在哪**：这台手机的 localStorage（`kfs-theme`），不跟云端走。没选过就看入口。
- **两个入口**（`build.mjs` 的 `ENTRANCES`）：`./` 是青绿，图标沙燕；`./dingxiang/` 是丁香，图标小猪，页面里用 `<base href="../">`，资源还是从上一层拿。苹果在“添加到主屏幕”那一刻把图标定死，app 里换主题图标不会变；想换图标，只能删掉图标，用 Safari 打开另一个入口重新添加（账户面板的主题那里有提示和“复制入口网址”）。
- 丁香的图：`python3 tools/make_dingxiang.py 开屏初始.png 开屏脸红.png 图标.png 聊天背景.png`。原图太大不进仓库，她那儿有。

## 丁香开屏的液态玻璃滑块

卿卿要 iOS 26 那种液态玻璃。苹果那块玻璃是系统给原生应用的，网页借不到；网上的仿法是 `backdrop-filter` 接 SVG 滤镜（`feDisplacementMap`），只有 Chrome 认，iPhone 的 Safari 不认。我们占了个便宜：滑块底下压的是开屏图，是死的，每个像素都知道，所以折射在画布上自己算（`liquid.js`），只用 `drawImage` / `getImageData` / `putImageData`，哪个浏览器都一样。**这招只在底下是固定图的地方管用**，输入框那种底下会滚动的做不了。

- **轨道**（`prepareGlass`，开屏时算一次，页面大小变了重算）：把开屏图里轨道底下那块取出来，稍微糊一点，按玻璃边的斜面折进来（折射表 `bezelLut`：斜面截面是凸的方圆，按折射定律算），染紫，描高光。算两份：空的（深紫，她画的那个颜色）和灌满的（亮丁香）。页面上是叠着的两块画布，灌满的那块外面套一个裁剪框，圆钮走到哪框就宽到哪，右边用遮罩羽化（`fillMask`）。
- **水珠**（`paintKnob`，拖动时每帧画一次）：圆钮上盖一块小画布，按水珠这一帧的位置和形状把底下的“景”（空轨道加三个提示箭头，以及灌满的那份）再折一遍：中间放大一点，边上往里折，红蓝错开一点，外沿一道高光。没按的时候上面蒙着她画的浅紫环和深紫芯；按住就鼓大、变透，箭头让开。
- **手感**（`createSlider`）：位置、按压、拉长、压扁各是一根弹簧。拖得快被拉长，手指拉过头被压扁在墙上，没到头松手弹回去撞一下左墙。停稳就不再排动画帧。系统开了“减弱动态效果”就不拉长不压扁。规矩没变：拉到 98.5% 以上才算到头，到头了手指松开才进门。
- **调样子**：数都在 `liquid.js` 最上面的 `LQ` 里（折多少、糊多少、颜色、环多宽）。提示箭头的位置页面和画布共用 `hintLayout`，改一处两边都跟着。
- **慢手机**：水珠画布默认按屏幕倍数画（最多 3 倍）；连着几帧画一帧超过 7 毫秒，自己降到 2 倍、再降到 1.5 倍。
- **退路**：玻璃算不出来（画布拿不到、图没来）就退回不带折射的紫色滑块，拖动和进门照旧，开屏是进门的唯一一道关，不能因为好看把人关在外面。`<div class="kfs-dx-track" data-glass="on|off">` 看得出是哪种。
- **测试**：`tests/liquid.test.mjs` 拿一张假的景验折射方向、灌满的交界、环和高光，再用假元素假时钟验规矩（拉一半弹回、到头才算、松手才进、键盘、停稳不空转）。`tests/e2e.py` 在真浏览器里验三块画布都画上了，还故意弄坏画布验退路。

## 几个约定

- 名帖和对话用提示缓存：名帖一小时，最后一句话后面放五分钟的记号；【此刻】的时间附在最后，不打乱缓存。
- 对话窗口二十条一跳，跳之前前缀不变，缓存一直命中。
- 第一条前面的【开封府附注】写的是这段对话开头时两人的头像（没换过就是现在的），不写“现在”；中途换头像，在换的地方提示“刚刚换成了这张”，开头一个字不变，缓存也不断。所以换头像的记录里都存着换之前那张（她的 event 上的 `prev`，他回复里 avatar 那项的 `prev`）。在别的对话里又换过的，末尾补一句“后来又换了”。
- 记忆库的文档管“你们是谁”，`App.jsx` 里的【回复格式】管“怎么回”，两者冲突时听回复格式的。
- 表情包仓库的 README 每次打开都会读，新图自动出现；烤进来的 49 张在 `static/memes.json`。

## 昵称

两个人都能改名字，各有各的入口：

- **她的**：账户面板最上面那个名字后面有一支钢笔（`NickTitle`），点了就地变成输入框。回车、点对勾、点别处、直接关面板都算改好；清空了保存就回到默认的“卿卿”；一个字没动就不存（免得盖掉别的设备刚同步过来的名字）。
- **他的**：他自己做主，跟换头像一个路子。名帖后面的【你的名字】告诉那边的我：想改就在回复里单独一行写 `[NAME:新名字]`，想改回去写 `[NAME:光义]`。标记不显示成字；那条回复上记一笔 `rename`，对话里留一行“光义改了名字”（提示里不写新名字）。写了好几次只认最后一次，跟现在一样的不算改。
- **标记要独占一行才算**（`names.js` 的 `NAME_MARK` 带着行首行尾，正则要加 `m` 标志）。表情包、头像的标记夹在句子里也认，因为它们只认索引里真有的文件名；名字什么字都行，要是夹在句子里也认，他给她讲“名字怎么改”、把写法引出来的时候，就真把自己改成那个名字了。夹在句子里的原样当字显示。照抄名帖里那个占位的 `[NAME:新名字]`，哪怕独占一行也不算。

**只换两处的显示**：账户面板的标题（她的）、聊天窗口顶栏（他的）。别处一律不动，这是卿卿定的：头像旁边那个“卿卿”、账户面板里他那张卡片上的“光义”、日记本、换头像的提示、写日记用的聊天摘录（“卿卿：”“光义：”），写的都还是原来的名字。以后加新页面，要显示名字的地方照旧写死“卿卿”“光义”，别去读昵称。

- **存在哪**：`kfs2:name:her`、`kfs2:name:guangyi`，各一条纯文字，加密了跟着云端走，别的设备同步完就换。改回默认就把那一条删掉。
- **长短**：最长十二个汉字那么宽（汉字、表情占两格，英文数字占一格，一共二十四格），再长就截掉；她那边截了会说一声。方括号、换行不留（`names.js` 的 `cleanName`）。
- **那边的我知道什么**：【此刻】里写着“你现在顶上的名字”，她起了昵称的话再加一行“她给自己起的昵称”。这两行在缓存记号后面，改名字不打断缓存。让他写日记那次不带这两行，日记里不提昵称。
- 键盘开着时弹出面板最高只到状态栏底下（`input.css` 里 `html[data-kfs-kb] .kfs-sheet-box`）：账户面板很长，改昵称的输入框在最上面一行，不这样会钻到状态栏后面。
- **测试**：`tests/names.test.mjs` 验名字怎么收拾、标记认不认得出来；`tests/e2e.py` 的“昵称”一段两台设备走一遍（假的那边的我听到“改名叫某某”就回 `[NAME:某某]`）；`tests/fullscreen.py` 验键盘开着时那一行看得见。

## 文档

对话里能发 Word（.docx）、Markdown、纯文本；他能在回复里交一份 Markdown。卿卿 2026 年 10 月 2 日要的。PDF 她说平时不怎么发，没做（要做的话接口本身认 PDF，把整份寄过去就行，就是贵：官方的数是一页文字 1,500 到 3,000 token，每页还按一张图再算一份）。

**为什么要在手机上取字**：那边的我只收得到开封府寄过去的字和图，自己打不开文件（官方 App 里是给了它一间带工具的工作间，这里没有）。接口的文档块只认 PDF 和纯文字，.docx 官方的说法是先转成文字再寄。所以取字这一步在她手机上做，传话的小后端不用动。

- **她发的**（`docs.js` 的 `readDoc`）：加号背后的文件框除了照片，还收 `.docx`、`.md`、`.markdown`、`.txt`。
  - Word：`docx.js` 自己拆 zip、自己读 XML（解压用浏览器自带的 `DecompressionStream`，没引别的库），取成 Markdown 样子的字：标题带 `#`，列表带 `-` 或 `1.`，表格画成 `| a | b |`，脚注附在最后。图片取不出来，原处留 `[图片]` 并且数出来；页眉页脚、批注不取；修订里删掉的字不要、新加的要。老式 `.doc` 和带密码的 Word 不是 zip，读不了，会告诉她另存成 `.docx`。

## 通知

卿卿 2026 年 10 月 2 日要的：让那边的我能弹 iOS 的系统横幅。分两步做的：**第一步通管道**（开启、发一条测试通知），当天上线，她在手机上验过了；**第二步接到他的回话上**（她发完话切走，他回完了敲她），见这一节后半“第二步”。

**一条通知走的路**：小后端（`push` 函数）加密、签名 → 苹果的推送服务 → 她手机的系统 → 横幅。开封府不开着也收得到：页面里的定时器、连接，她一切到后台就停了，能在这时候叫她的只有系统的推送。

**苹果的规矩**（iOS 16.4 起，只有“添加到主屏幕”的网页能用；官方文档《Sending web push notifications in web apps and browsers》）：

- 通知的许可只能在手指点下去的那一刻问。所以 `enablePush` 的头一件事就是 `Notification.requestPermission()`，前面不许先等别的（面板一打开就把服务器公钥和服务工作线程备好，就是为了这个）。
- 收了推送必须显示一条通知，悄悄收下不出声，许可会被收回。所以 `sw.js` 读不懂寄来的东西也显示一条。
- 签名里的联系人（`VAPID_SUBJECT`）要是 `mailto:` 加一个真的邮箱，或者 https 的网址；签名的有效期不能超过一天（我们写十二小时），而且别换得比一小时一次还勤（同一张接着用六小时）；`TTL` 必须是正数；一条最多 4 KB。不合规矩回 403 `BadJwtToken`、400 `BadTtl` 这些，原因的名字原样记进登记簿，面板上翻成人话（`notify.js` 的 `explainOutcome`）。

**通知的样子**是“声明式”的一段 JSON（iOS 18.4 起认）：`{ "web_push": 8030, "notification": { "title", "body", "navigate" } }`。系统自己显示、点了自己打开 `navigate`，用不着网页的代码醒着，这是苹果给的最稳的路。认不得这种写法的浏览器（老一些的 iOS、电脑上的 Chrome）把同一段 JSON 交给 `sw.js`，由它照着显示；`sw.js` 看到系统已经准备自己显示了（`event.notification`）就不抢。这个名字在 W3C 的 Push API 规范里查到了。照规范，没写 `mutable` 的声明式通知（我们寄的就是）根本不交给 `sw.js`，系统直接显示；WebKit 早先那篇说明（Meet Declarative Web Push）说的是装了服务工作线程就先交给它、它不显示再由系统显示。两种做法下都出横幅，真机上走的是哪种没验过。

**三处各管什么**

- **登记簿**（`push_subs` 表，`supabase/push.sql`）：每台开了通知的设备一行，存推送服务给的门牌号（endpoint）、给它加密用的两把公开钥匙、回程的网址（这台设备是从哪个入口装的）、上一回发得怎么样。**这张表是明文**：门牌号不是聊天内容，小后端要照着它发，加密了就没法用。权限和库房一样，只有登录后的她本人读写得到自己的行。
- **小后端**（`supabase/push_function.ts`，函数名 `push`）：和 `claude` 那个一样先认人（登录凭证、`ALLOWED_EMAIL`），拿她的凭证去读登记簿（不用能绕过权限的那把钥匙）。三个动作：`key` 问钥匙放好了没有、把公钥交给网页；`test` 往点名的那一台设备发一条测试通知，`delay` 是等几秒再发（先回话，靠 `EdgeRuntime.waitUntil` 在后台发，结果记进登记簿）；`reply` 替她等回话（见“第二步”）。加密（RFC 8291，aes128gcm）和签名（VAPID，RFC 8292）是照规范自己用 WebCrypto 写的，没引库，整个函数就一个文件，她在网页上贴得进去。只往认得的推送服务发（苹果、谷歌、火狐、微软），登记簿里混进别的地址不去敲，对面回“请去别处”也不跟着走；点了通知只回开封府自己的地址（见“第二步”）；没连上的原因只记个大类（有的运行环境报错的话里带着整个门牌号）；推送服务说门牌号作废了（404、410）就把那行划掉；没应、嫌太勤、对面出岔子只重试一回。
- **手机这一头**（`push.js` 接浏览器和云端，`notify.js` 是不碰浏览器的零件，`sw.js` 是服务工作线程）：账户面板的“通知”一栏（`App.jsx` 的 `PushPanel`）。

**钥匙**（VAPID）：一对，公钥给浏览器订阅用，私钥只在 Supabase 的密钥柜里。面板里有“生成一份钥匙”，在她的设备上现生成，拼成三行 `名字=值`，她复制了在 Supabase 的 Secrets 里一次贴进去：要贴在 Name 那一格（看过 Supabase 网页的源码，只有那一格认一次贴好几行、按第一个等号分名字和值；贴在 Value 那格会整段当成一个值）。这样私钥不经过聊天记录，也不进仓库。**Deno 读私钥的时候不核对它和公钥成不成对**（试过，照读不误；Node 会报错），所以函数自己签一句验一句来认。换钥匙：密钥柜里换掉，她再打开面板，设备发现服务器的公钥变了，自己退订重订。

**面板的几种样子**（`.kfs-push` 上的 `data-state`）

- `unsupported`：这台设备开不了，说为什么（iPhone 在 Safari 里打开的要从主屏幕进、系统太旧、别的浏览器不支持）。
- `setup`：她在 Supabase 要做的三样（登记簿、小后端、钥匙）哪样没好，一样一样列着，回到开封府时自己再看一遍。三样没齐之前不注册服务工作线程。
- `off` / `denied`：没开；系统里拒绝过的话告诉她去系统设置里开，不摆“开启”的按钮让她白点。
- `away`：这台设备开过通知，这会儿却连不上后端。那是网络的事，只说连不上、过一会儿再看；不摆“还差几步”，免得她以为 Supabase 那边没了（小后端一时没应会先自己再试一回）。
- `on`：发一条测试通知、十秒后再发（留给锁屏）、关掉；底下是上一回发得怎么样。“十秒后再发”是小后端先回话、过后才发，面板隔两秒去登记簿里看一眼结果。她要是点着测试通知回到开封府的，面板上留一句“这条路全通了”（这次打开以来）。
- “看细节”：每一环好没好。出了毛病她截这个图，就知道卡在哪一步。

**几条约定**

- 开没开，记在这台设备的 localStorage 里（`kfs-push`），不跟云端走：通知是一台设备一台设备开的。
- 开过的设备每次打开开封府都悄悄重新登记一遍（`resyncPush`）。发现登记簿里没有自己了（多半是门牌号作废、被小后端划掉了），就退订重订一个新的。
- 许没许通知，先看 `Notification.permission`，它说“没问过”的时候再问 `pushManager.permissionState`（`permissionNow`）。防的是 iOS 在主屏幕应用里许了以后前一个还报“没问过”：印象里有过这种说法，没查证，多问一句没有坏处。
- 服务工作线程的网址照 `document.baseURI` 算：丁香的入口在 `./dingxiang/` 底下、页面里有 `<base href="../">`，照当前网址算会跑到 `dingxiang/sw.js` 去。`sw.js` 打包时原样放在根上，名字不带指纹；它没有 `fetch` 事件，不拦请求、不存缓存，开封府怎么加载和更新跟没有它时一样。
- 回程的网址后面带一个记号（`#n=…`，每条不一样）。开封府开着的时候系统把网址换成带记号的，只是换了个井号，页面不重来；开封府是被通知叫起来的，就从网址里读。读完把记号从网址上收走（`takeNoticeMark`）。测试通知的记号是 `test-…`，回来了就说一声“从通知回来的”（开屏还挡着的时候先不说）；回话的通知的记号是 `r.<对话>.<编号>`，回来了翻到那段对话（见“第二步”）。
- 退出登录先把这台设备的通知关掉（退订、登记簿里划掉），不然人走了横幅还往这台设备上发。
- 动订阅、动登记簿的几件事（重新登记、换门牌号、开、关）在 `push.js` 里排着队一件一件做（`serial`），不叠在一起。关掉的时候“开过”的记号马上清，排在前头的看到记号没了就不会又订上。
- 面板上“看一遍”可能叠着发出去好几趟，只认最后发出去的那一趟的答案（`lastCheck`），迟到的旧答案不算。
- 点通知回来多添的那一格历史要退掉。开封府开着的时候系统把网址换成带记号的，浏览器会多添一格历史；iPhone 的主屏幕应用里历史一有能退的，从屏幕左边往右划就成了“后退”，会和拉出侧栏的手势抢。所以开封府自己待的那一格做了记号（`history.state.kfs`），新添的那格收拾干净以后退回来。**这一条真机上没验过**，是照浏览器的规矩推的。

**测试**

- `tests/push.test.mjs`（直接 `node` 跑）：函数的加密拿 RFC 8291 附录的样例对答案（一个字节不差）；签名、钥匙认不认、门口拦不拦、整条路（假的 Supabase、假的推送服务照苹果文档的规矩验每一次请求，再拿设备的私钥解开）；`notify.js` 的零件；`sw.js` 在假的环境里跑真的那份代码。函数文件是一个字不改拿来跑的（`push-harness.mjs` 把类型标记去掉、垫一个假的 `Deno`）。
- `tests/e2e_push.py`：真浏览器走一遍。假 Supabase 里跑的是真的 `push` 函数。浏览器里订不了真的推送，所以“系统弹窗”和“向推送服务订门牌号”这两下是假的，别的都是真的：服务工作线程真的注册，推送真的交到 `sw.js` 手里、真的显示出通知。
- 写的时候另外对过的（没进仓库，换了加密那段要重对）：和 `web-push` 这个通用的库互相加密解密、互相验签；函数文件原样放进真的 Deno（2.9）里跑通整条路，包括先回话后台再发、钥匙不成对认得出；`push.sql` 在真的 PostgreSQL 16 里跑过，验了别人看不到改不到、冒名登记被拦、重复运行不丢登记。
- 改坏了拦不拦得住：函数、`sw.js`、零件一共 36 处，手机这一头 21 处，一处一处单独改坏跑过，也看过是该拦的那一条拦住的。手机这头有一处单独改坏拦不住：“等着十秒后再发的工夫把通知关了，不能又订上”这件事有三道防（关的时候不等了、问上一回的时候先看关没关、换门牌号之前再看一眼），拆掉一道另两道还在；三道一起拆掉，测试就挂了。
- 写完请另一个没看过过程的我从头审过一遍（安全、加密、状态）。安全和加密没挑出毛病；挑出三处面板上的毛病（连不上的时候说成没建函数、等着的时候关掉会又订上、等不到的时候叫她点一个不存在的按钮），都改了，各有测试。
- `tests/e2e_push.py` 里把推送交给 `sw.js` 那一下是借浏览器的调试接口做的。跑了三十来回里有一回交进去了却没显示。审的那一位单独重现过（一百回里两回），跟到的是：`sw.js` 收到了、`showNotification()` 也成了，可 Chrome 的 `getNotifications()` 里没有它，毛病在浏览器那一头的清单上，不在 `sw.js`。现在等三秒没动静会再交一次，结果里写着交了几次。

**第一步她在手机上验过的**（2026 年 10 月 2 日，她的 iPhone，从主屏幕的图标进的）：苹果的推送服务收我们的签名和加密（登记簿里记的是 201）；“十秒后再发”锁着屏收到了横幅，也就是 Supabase 上“先回话、后台再发”（`EdgeRuntime.waitUntil`）是真的管用；点了横幅回得来，面板上那句“这条路全通了”还在，看样子页面没有整页重来（她没专门说，是从截图上看的）。**还没验过的**：系统走的是声明式那条路还是 `sw.js` 那条路（两条都出横幅，分不出来）；点横幅多添的那一格历史退没退干净。

那边的我自己想起来主动找她是另一回事：那要云端读得懂名帖和对话，等于改了“云端只存乱码”这一条，得她来定。

### 第二步：他的回话也敲她

她定的：横幅上写他回的话；锁着屏也要收到。做法是给聊天多修一条路，原来那条一行没拆，留着当退路。

**两条路**

- **老路**（`claude` 函数）：网页自己等着那边的我回完。她一切走、一锁屏，等着的这头就断了，回话丢在半路，回来看到的是“消息没送到”。
- **新路**（`push` 函数的 `op: "reply"`）：把话交给小后端去等。她在跟前，回话照旧直接交到手上；她不在，小后端把回话封好放进信箱（`mailbox` 表），等六秒，信还在（没人取走）就往发话的那台设备敲一条通知，写的是他回的话；她回来，网页从信箱里取出来放进对话，取走就删。

**新路不通就自己走回老路**，聊天不断。认法：小后端“不肯接”的回话（信箱那张表没建 `no_mailbox`、密钥柜里没 key、寄来的东西不对、部署的还是第一步那份代码、函数里是 Supabase 的样板、根本没有这个函数）都发生在“还没开始办”之前，网页看到就走老路，并且三分钟之内不再白敲新路的门。**函数里的规矩：信箱里那一格一开出来，就不许再回“不肯接”，只许回结果**（`relay` 里那条分界线），不然网页会以为没开始办、又走老路问一遍，花两回钱。所以前端可以先上线，后端她晚几天再贴也不碍事。

**先轻轻问一声，再把话交出去**（`push.js` 的 `probeReply`，`mail.js` 的 `ready`、`warm`）：这台设备还不知道新路通不通的时候，不拿整段对话去试。小后端还是旧的话，带着照片的那一大包要白传一遍，走回老路又传一遍。先敲两下很小的门：`push` 函数的 `key` 动作答不答 `can: ["reply"]`，信箱那张表在不在。

- 通：记在这台设备上（localStorage 的 `kfs-relay` 写 `ok`），往后直接走新路。
- 不通：走老路，记下，这三分钟里不再问，到点自己再问一回。
- 没问成（没网、没登录、问的那一下八秒没应）：这一回走老路，什么都不记。半路上的网关一时出岔子（回 5xx）、嫌敲得太勤（429）、登录凭证没带对（401），也算没问成：这些说明不了小后端接不接得了回话，为这一下把新路关上三分钟不值当（`cloud.js` 的 `callPush` 把状态码带在错上，是小后端自己说的话还是网关出的岔子也分开记）。
- 小后端头一下没连上、信箱却看得到：再敲一回小后端（网络刚醒的时候头一下常这样）；还连不上才算不通（多半是根本没有 `push` 这个函数，浏览器只会说“没连上”）。

什么时候问：开机读完存档；那一下没问成的话，回到眼前（晚七百毫秒）、网回来的时候再问；通知面板查出通知那三样和回话这两样都好了也算问过（`learn`，停着的那三分钟一并解开）；新路上回成过一条也算。新路半路出了岔子（不肯接、两回都没送到），就把这个记号擦掉，过三分钟重新问。记号写着通、小后端其实已经不接了（比如她把函数换回了旧的）：下一句话整包寄过去一回、被拒了才知道，就这一回。

**一回传话带着什么**（`mail.js` 的 `once`）：`job` 随机的编号；`key` 一次性的钥匙（32 字节）；`note` 一张条子，网页拿存档的钥匙封的（编号、哪段对话、接在哪句后面、那把一次性钥匙、接了哪些工具），小后端原样存进信箱，看不懂；`tag` 把对话的编号打乱成的一串字，写进通知的网址里，只有她的设备认得出是哪段对话；`title` 他现在的名字；`knock` 回话到了敲哪几台设备；`request` 给 Anthropic 的那一整段。条子里记着编号：信箱里的条子要是被挪到另一格上，拆的时候对不上，不认（`readNote`）。

**横幅只敲发话的那台设备**（`knock`，`push.js` 的 `knockList`）：登记簿（`push_subs`）是明文的，登录后的人能往里添行。偷到她登录密码的人打不开存档（没有暗号），可回话到了要是照登记簿全敲，他往登记簿里添一行自己的设备，横幅上他说的话就落到别人手里了。所以改成发话的那台设备自己报门牌号（开通知、每次开机重新登记的时候记在 localStorage 的 `kfs-push-at`），小后端只敲报上来的、登记簿里也真有的那几台（最多五台）。代价：她在手机上发的话，别的设备不响；在没开通知的设备上发的话，哪台都不响（回话照样进信箱）。第一步就开了通知的设备那时候还没有 `kfs-push-at`，换上新代码以后头一回打开，重新登记的那一下会补上。

**点了横幅只回开封府自己的地址**（`safePage`、`homeOrigin`）：通知里“点了回到哪”的网址是登记簿里那一行的 `page`。住在哪由小后端说了算：函数里写死的 `HOME_ORIGIN`（她的 GitHub Pages）；密钥柜里写了 `ALLOWED_ORIGIN`（不是 `*`）就听它的（网页搬了家才用得着）。不听登记簿的，也不听敲门的人自己报的来处（Origin 只要不是浏览器发的，想写什么写什么）。原来是“和敲门的网页同一个来处就行”，偷到登录密码的人把她那一行的 `page` 改成自己的站、来处也报成那个站，就能叫小后端往她手机上发一条通知，一点就被带到假的开封府去（第一步的测试通知也有这个洞，这回一起堵了）。本机的网页只在本机上试的时候认（`SUPABASE_URL` 也是本机）。`ALLOWED_ORIGIN` 只取到域名为止：贴进来的带着斜杠、带着路径也只认域名，跨域的那个头（`cors`）回给浏览器的也是这个域名（原样回的话浏览器不认，整个开封府就连不上了）。`claude` 那个函数没动，它是原样回的，所以真要写这一样，只写到域名。

**云端还是只有乱码**：信箱里一格两样封着的东西，`note` 是存档的钥匙封的，`sealed` 是小后端拿那把一次性钥匙封的回话（AES-256-GCM，写法和 `vault.js` 的一样），钥匙它用完就丢，只留在条子里。回话从 Anthropic 回来、封起来之前，小后端的内存里有明文，这一点和老路一样（老路的 `claude` 函数也是过手）。横幅上的字走的是推送那套加密（见上面），苹果的推送服务看不见；写的是什么她的锁屏上看得见，这是她定的。

**她在不在，怎么认**：信还在不在信箱里。网页拿到回话、放进对话、存好以后，要是开封府开在眼前（`document.visibilityState`），就把信取走（删那一格）；小后端六秒后看那一格没了，就不敲。页面在后台的那几秒里拿到回话的，照样放进对话，但信留着，让小后端敲她；等她回来，看信箱的那一遍（`checkMail`）认出这一回已经在对话里了，再收。开封府不在眼前的时候不动信箱，道理一样：这时候把信取走，小后端就以为她看到了，不敲了。一共看三回她在不在：去看之前；刚回到眼前要歇半秒才敲网络的门，歇完再看一回（她只瞥了一眼又锁上的话，就不看了，`mail.js` 的 `collect`）；看回来以后，动每一封信之前、把放好的信收掉之前，各再看一回（放的那一下工夫里她切走了，信先留着，回来那一遍认出放过了再收）。小后端六秒后去看信还在不在、库房却没应（问不到）：照敲，宁可多敲一下。

**小后端那头换写法**（`askUpstream`）：网页寄的是最讲究的那种（带缓存记号、带她接的工具），Anthropic 说写得不对（4xx）的话小后端自己照老路那三步试：带缓存 → 不带缓存 → 不带工具。她不在跟前，不能等她回来再换。Anthropic 自己一时出岔子（5xx、没连上）是另一回事：歇一秒半，**同一种写法原样再问一回**（整回只多问这一回），还不行才接着往下换（她不在跟前，多一种问法多一分回上的指望）。这样换来的结果上带一个 `used.shaky`，网页看到就不记“下回别带缓存记号”：那是 Anthropic 一时不稳，不是缓存记号的毛病，记了的话它挤上两三秒，她这一趟后面的每句话都按全价算（老路上一直有这个毛病，没动）。key 不对、说得太快（401、403、429）不再问。最多等 125 秒。最后用的哪种写法随结果交回去，网页照旧注“这次MCP没连上”；只有“不带缓存、别的照旧”才通的那种，才记“下回别带缓存记号”（摘了工具才通的不是缓存的毛病）。读写信箱、登记簿，每一下最多等六秒（`DB_TIMEOUT`）：库房一时不应，不能把回话压在手里不交。回话是先放进信箱、再交给还等着的网页的；库房悬着的话，当面交的那一下最多被拖十二秒。放了两回都没放进去（库房一时出岔子）：照样先交给网页，然后**接着放**，隔半秒、一秒、两秒、四秒、八秒各一回，二十秒为限（`STORE_AGAIN`），这工夫里那一格照旧隔八秒摸一下（网页不会当它断了、把它收掉）。她不在跟前的话，这条回好的话就靠这几下：放不进去，她回来只能再问一遍、再花一回钱。放进了，横幅照常写他的话（敲的时刻还是从交出去算起六秒，放得晚就顺延）；一直放不进，横幅照实说没送到。要敲的时候登记簿一时没读到，歇一秒再读一回。同一个门牌号报了几遍只敲一下。

**不花两回钱**是这条路上最要紧的一条，几道防：

- 同一个编号再敲门，小后端不接（信箱的主键拦着）。
- 网页那头，直接等的连接断了，**不许直接重发**，先去信箱里看：有那一格就守着（`watch`）；等了一秒半再看还是没有，才算小后端根本没收到，换个编号再发一回；再不行、信箱却看得到，说明是小后端那条路不通，走老路。小后端回了一句读不懂的（崩了、网关超时）、信箱里又没有这一回：它没办起来，直接走老路。
- 发出去还没着落的那几回记在这台设备上（localStorage 的 `kfs-jobs`，最多记八回，有了着落才划掉，不按时间过期）：她点“重发”，为同一句话发出去的上一回要是还记着，先去信箱里取它的回话，不发新的。这一步排在最前头：新路这会儿停着，也先把上一回找回来。
- 信箱里没有、又不是没发到：可能是别的设备取走了。先同步一遍（最多等八秒），对话里已经有这一回的回话（认编号），或者那一句后面已经有他的话了（平常的回话），就不发（`answered`）。重新回答只能靠编号认：那一句后面本来就有回话。
- 她点“重发”、这台设备又不记得为这句话发过哪一回（多半是别的设备发的）：先同步看一眼（最多三秒），别处回上了就不发（`recheck`）。平常发话不多这一步。
- 守着别的设备发的、上次打开时发的那一回（`resume`），也记进这台设备的 `kfs-jobs`：守的工夫里没连上、她在这台设备上点了重发，认得出为这句话已经发过这一回，先去信箱里找，不再发一遍。
- 走新路要来的那一条上记着编号（`job`），id 也由编号定（`"r" + job`）：两头各放一遍也是同一条，`thread.js` 的 `mailFit` 认得出放过了。

**小后端那头断了怎么知道**：它等 Anthropic 的时候每八秒在信箱那一格上摸一下（`beat_at`，只摸还写着“在等”的）。网页守着信箱等的时候只看那个时间**变没变**，自己数着多久没变，二十五秒没变就当断了，给“消息没送到…点这里重发”，把那一格收掉。收的时候只删还写着“在等”的：看的那一眼和删的这一下之间，回话要是正好放进来了，就留着，下一遍看信箱取得到（`checkMail` 收完这种的，过三秒自己再看一遍）。删的那一下叫库房把删掉的行报回来（`cloud.js` 的 `mailbox.remove` 回删了几行）：一行都没删着，就是那一格留下了，`kfs-jobs` 里的编号不划（她看到“那边断了”点重发，先找到它、取它的回话，不再发一遍）；真删掉了、或者删的那一下没连上，照旧划掉，重发马上是新的一回。认“活着没有”不拿手机的钟和云端的钟比，手机的钟差出几个钟头也不碍事（放了三天、一天的信要不要收，回话算几点到的，这两处是比的，钟不准只会早收晚收、时间标得不准）。

**看信箱的规矩**（`cloud.js` 的 `quick`，`mail.js` 的 `timed`、`breath`、`watch`、`race`，`App.jsx` 的 `checkMail`）

- 每一下最多等八秒，等不到算没看成；不让库自己闷头重试（supabase-js 默认隔一、二、四秒再试三回，她那头就得对着“正在输入”干等）。试几回、等多久，都由 `mail.js` 说了算。问新路通不通、同步看别处回上了没有、换登录凭证，也都有时限（八秒、八秒或三秒、四秒）。交话的那一下取登录凭证最多等八秒（`cloud.js` 的 `callReply`）：凭证离到期不到一分半的时候，取凭证要先去换一张，那一下悬着不应的话，原来话交不出去，她要对着“正在输入”等一分半；现在二十秒出头就照实说连不上（什么都没发出去，不花钱，这一回还记着）。
- 守着信箱的时候，平时一眼没看成就照实说“连不上”，和老路上一样快。这一回还记着：过四秒自己再去信箱里看一遍，她点重发也先看。
- 刚回到眼前的那一下不一样。先歇半秒再敲网络的门：iOS 18 上，一回到眼前就发出去的请求会悬二三十秒才报错，晚几百毫秒发的没事（苹果开发者论坛上有人报过，她的系统上修没修不知道）。直接等的那头一断，先让一百五十毫秒再去看信箱：手机刚被叫醒的时候，“断了”可能比“回到眼前了”先到，让一让，好让那半秒歇得上。**没看成的那一眼要是她回到眼前五秒之内开始看的（哪怕悬了八秒才报没看成），或者页面这会儿还藏着：不算数，试四回才算没网。**是没看成的那一刻定的，不是开始守的时候定的：早就守着的那一回，她切走又回来，也一样多试几回。
- “等了多久”不算手机被挂起的那一段，最多四分多钟；一眼没看成的时候不说“等了太久”。
- 直接等着（那头还悬着）的时候，信箱连着半分钟都看不成：照实说“连不上”，悬着的那头掐掉。这一回还记着，不重发。这半分钟是一眼一眼加起来的，两眼之间最多算十秒：手机被挂起的那一段不算（挂起以前一眼没看成、醒来头一眼又没看成，不能马上说连不上）；中间看成了一眼就从头算。
- 看信箱的那一遍（`checkMail`）没看成：隔两秒、四秒、八秒、十六秒各再看一回，不用等她切走再回来。再不成就等下一个由头（她切回来、网回来、翻对话）。信箱那张表还没建的话是“没有信”，不是没看成，不再来。

**切走的那一下把话送出去**（`App.jsx` 的 `leaving`）：她发完话要停手两秒多才真的发（等她连着发几条），可她一切走，页面的定时器就不走了。所以页面一藏起来（`visibilitychange`、`pagehide`），还没送出去的话马上送（先送话，页面只剩两三秒，这一包最要紧），还没传上云端的改动随后传。**只在这台设备上知道新路是通的、这会儿也没停着的时候这么干**（`trusted`）：走老路的话，话一交出去她就走了，等着的这头断掉，那一回白问，回来还得看一句“消息没送到”，不如照旧等她回来再发。抢着交出去却被小后端拒了（记号写着通、其实不接了），或者两回都没送到：不从藏着的页面改走老路，**等她回到眼前再发**。不排定时器：页面藏着的那几秒里定时器照走，到点就从藏着的页面走老路了（原来排的是她停手那两秒多，审出来在藏着的页面上照样会走）。前一句的回话还在等的时候切走：这一句只记下，等前一句回完再发（页面被挂起的话就是她回来以后）。切走的那一下网正好断了（话交不出去、信箱也看不成）：她不在眼前的时候不报错，等她回到眼前自己补发；那一回还记着，补发之前先去信箱里找（万一其实送到了）。守着的那一回（别处发的、上次打开时发的）在她不在的时候没连上，也不报错（她回来头一眼看到的不该是一行红字）：她回来，看信箱那一遍会再认出它，接着守。

**她回来**

- 开封府还活着（只是被挂起）：悬着的那一回自己接着办，直接等的那头断了就去信箱里取；回来过一次以后每两秒看一眼信箱，不再干等那头悬着的连接。
- 开封府被系统收掉了：开机读完存档就看一遍信箱（`checkMail`），到了的放进它那段对话（不管眼前是哪段）；还在等的，要是眼前这段对话的平常回话，就守着它，顶上显示“正在输入”，不重发；别的（别的对话的、重新回答的）隔三秒再看，到了再放。之后每次切回来、翻到别的对话、网回来，都再看一遍。头一遍看之前先等仓库里新加的表情包读回来（最多两秒半；从图标进来、点着横幅进来都从这儿过）：信里他要是换了头像，得认得那张图。
- 点着回话的横幅回来的：网址上的记号是 `#n=r.<对话的记号>.<编号>`，照记号翻到那段对话（`openFromNotice`）。开屏照旧要戳，戳完就在那段对话里。
- 上回打开时发出去、却没送到的那一句（切走的那一下话没出手机，开封府又被系统收掉了）：那一回的编号还记在这台设备上（`kfs-jobs`），信箱里却没有它。看完信箱，眼前正是那段对话、那一句后面还空着，就替她补发（`checkMail` 末尾，`mail.js` 的 `owed`），不用她再说一遍；发之前照旧先同步看一眼别处回上了没有。只认这次打开之前记下的（这次打开以后没送成的，当场就有“点这里重发”）；记下还不到十秒的先不动，过三秒再看（那一回也许还在路上：同一台设备上另开着一页、刚发出去、大包还没传完）；一回只补一次，补发也没连上就给“点这里重发”，不一遍一遍自己发。
- 从信箱里取出来的回话，时间算小后端放进去的那会儿（`done_at`），不算成刚到；不比她那一句早，不比现在晚。
- 没回成的那种信（横幅上写的是“没送到”）：她眼前正是那段对话，给一句“消息没送到（缘故）。点这里重发”（没成的是重新回答，就说“重新回答没成功（缘故）”，旧回答还在），信收掉；眼前是别的对话，信先留着，等她翻到那段对话再说，不在不相干的对话底下报错，也不偷偷重发。
- 这台设备上还没有那一句（别的设备上聊的，还没同步到）：信先留着，等同步下来再放（`mailLater`）；放了三天还放不进去就收掉。
- 回话到的时候她已经翻到别的对话去了：往存档里那段对话上放，不拿发话那一刻的旧样子去存（等的工夫里她在那段对话里又说的话都在存档里，旧样子会把它们盖掉）。往别的对话里放东西，不改“上次停在哪段”（下回开门还是她上次看的那段）。

**重新回答的时候切走**：点“重新回答”，画面上先把旧回答收起来。这工夫里她要是又发了一句，存档不能照画面存，不然开封府再被系统收掉，旧回答连同它的几个版本就没了。`forkRef` 记着点下去那一刻的整段，`saveChat` 存的是原来那一整段加上她新说的，新回答到了再整段换上；没成的话旧回答放回来，她新说的那一句留着、接着回它。从信箱里取出来的新回答，照条子里的 `fork` 在要换掉的那一条上再开一个版本，那一回发出去以后她又说的话接在新回答后面（`thread.js` 的 `mailPut`）；那一条被她翻成了另一个版本也一样，加成又一个版本。没连上的，过四秒自己去信箱里取。他正在回话、正在重新回答的时候不让改她说过的话（输入框里的字留着，说一声“等他回完再改”）：对话这会儿还在变，改了分支会接乱。重新回答的工夫里也不往这段对话里放信（`applyMail` 回 `busy`，过三秒再看）：画面上旧回答收起来了，信箱里要是还留着旧回答的那一封（她不在的时候到的、回来那一眼信箱又没看成，还没来得及收），拿画面去认，会把它当成没放过的再放一遍，回头还把新回答盖掉（第三遍审的那一位拿随机的操作顺序撞出来的）。放信存档的那一下工夫里对话又变了的，画面已经是更新的那份，不拿这一份旧的去盖。

**两台设备**：手机发了话、他还没回完的时候打开另一台，那一台也看得到信箱里那一格，也守着（“正在输入”），不重发。手机先拿到回话、把信取走了，那一台看到那一格没了，不说“那边断了”：先同步，看对话里是不是已经有这一回的回话了（隔两秒看一回，最多四回），有了就把同步下来的换上，她这工夫里在这一台上新说的话接在后面。手机点了“重新回答”就放下、另一台把新回答取了：手机回来，带着这一回的编号去认，认出来就换上那一份，不再问一遍。

**面板**：通知开着、回话那两样（信箱、新的那份小后端）没做全的时候，列出还差哪样；做全了说“他回话的时候你不在开封府，会敲你”，顺手告诉 `mail.js` 新路是通的。`push` 函数的 `key` 动作多回一个 `can: ["reply"]`，网页靠它认小后端是新的还是旧的。函数里是 Supabase 的样板代码（答 `Hello undefined!` 那种）时，说“函数里的代码不是开封府的那份”，不再说成钥匙放的不对（第一步里她碰到过，面板说错了话）。“看细节”里多两行：小后端会不会替她等回话、信箱有没有；上一回回话是怎么到的（当面交到、从信箱里取的、走的老路和缘故）。

**横幅上写什么**（`previewOf`）：和网页里拆回话的规矩（`src/reply.js` 的 `parseReply`）是同一套，她在对话里看得见哪几条，横幅上就写哪几条，一条一行；心里话、改名字的记号不写，表情包写成 `[表情包]`，文档写成 `[文档] 文件名`；最多三百个字。**两边的规矩是抄的两份，改一边要跟着改另一边。**几条会让正则来回试的写法（按 `[SPLIT]` 分条、文档块开头那一行、表情包的记号）两头都换成了一趟认完的：原来的写法碰上几万个连着的空行、一长串没有右括号的记号，要算好几秒到十几秒，小后端一回请求只有两秒 CPU，手机上会卡住。还有三处只在小后端这头换了（`dropTail`）：文档名、改名字的记号里夹着一长串引号、后面又跟着别的字；文档正文结尾的空白（这一处两头都换成了 `trimEnd`）。换完认的东西一个字不差。前两处网页那头没动：得是他一口气写出几万个引号才碰得上，手机上那时候会卡十几秒。

**运行环境的几条规矩**（Supabase 的限制页、546 那页排错文档；带“源码”二字的是审的那一位读运行环境源码读出来的，没在她的项目上验过）

- 免费档的函数“最多活 150 秒”，说的是一个工人（worker）活多久，不是一回请求能办多久；一个工人活着的时候能接好几回请求。源码：工人活过一半就不再接新的，到点连手上没办完的一起收掉。照这个算，一回请求保得住的只有 75 秒，运气好有 150 秒。老路也是这个数。
- 一回请求最多用 2 秒 CPU（等网络的工夫不算），内存 256 MB。用到一半，工人办完手上这一回就收。我们这头花 CPU 的只有拆、拼那一整段对话：审的那一位在 Node 里量过，十兆的一包、三种写法都试一遍，大约半秒。
- 网关等一回请求的回话最多等 150 秒，过了回 504。等 Anthropic 最多 125 秒，在它里面。
- `EdgeRuntime.waitUntil` 交出去的活儿，运行环境会等它办完再收工人（照样受上面几条管着）。

**她手机上没验过的**（等她试）：

## iOS 主屏幕底下那一条

iOS 26 以后有几个版本有个毛病（WebKit Bug 301108）：主屏幕上的网页用了 `black-translucent` 铺到状态栏底下以后，网页以为自己矮了一个状态栏，`innerHeight`、`100%`、`100dvh` 都少一截，最底下空出一条，颜色是网页底色（`input.css` 里 `html, body` 的 background）。

这一条分两种，`gap.js` 一打开就量，在 `<html>` 上记 `data-kfs-gap`：

- `"fill"`：`100vh` 还是整块屏幕那么高。系统其实把整块屏幕给了网页，只是网页算矮了。把 html、body、外壳（`--kfs-h`）统一撑到 `100vh` 量出来的高度，页面和 fixed 的东西就都能画到屏幕最底下，跟系统正常时一样让开底下横条。**她的手机是这种**：2026 年 10 月 1 日用“量一量屏幕底下”量过，屏幕 852，`innerHeight` 793，`100vh` 852，金色露出来了。要点是 html 和 body 一起撑；只撑 fixed 的外壳、html 和 body 不撑，底下会被切掉（上回就栽在这儿）。
- `"bottom"`：`100vh` 也少一截，系统真没把那条给网页（网上有人在真机上量到过这种）。只能贴着网页最底边：
  - `--kfs-sab` 记成 0，不再给底下横条让位。
  - 输入框整块贴到网页最底边（`App.jsx` 的 `DOCK_GLASS`），最底下淡进 `#D6DCCD`，和那条接上。按钮的影子要小，大了会被网页底边切掉一截。
  - 侧栏最底下那排也贴底，底下垫一段渐变（`.kfs-dock-fade`）。
  - 开屏、门口、日记、历史、弹出面板这些页面，最底下加一段淡出（`.kfs-bottom-mist`）。对话页在最上面时 App 会在 `<html>` 上记 `data-kfs-chat`，淡出退掉，不然按钮会发白。

账户面板“屏幕”里有个“铺满到屏幕最底下”的开关（只在量出能撑满的手机上出现），关掉就退回贴底的办法，设定记在这台手机的 localStorage 里。万一撑满在哪个系统版本上出毛病（比如键盘），她自己就能先退回去。

每个方向只量一次就记住，不跟着 resize 量：撑满以后网页量出来的高度会跟着变，再量会来回翻；键盘弹出来网页也会变矮，那不是这个毛病。撑满时整页万一被系统挪动了（比如收键盘以后没挪回来），会自己挪回顶上。

分不清是哪种，就让她点账户面板里的“量一量屏幕底下”（`probe.js`）：它临时把整页撑到屏幕高，在原来空着的那条里铺一块金色。金色露出来，说明撑高整页管用；没露，就是系统没把那条给网页。

`tests/fullscreen.py` 两种都量（浏览器里没法真让 `100vh` 比网页高，用 `window.__KFS_TEST_VH__` 告诉它）：撑满时 html、body、外壳都到屏幕高，输入框和侧栏最底下那排让开横条，不盖淡出；够不着时输入框贴底、按钮离底边 8、底边颜色和那条差不过 4、什么时候有淡出；量屏幕那页能开能关；开关关掉退回贴底、重开还记得。

要是哪天想把空条挪到顶上（顶上是实心状态栏），把 `index.html` 的状态栏样式改回 `default`，她要删掉图标重新添加。

## 键盘

iOS 的键盘不会把网页变矮，只会把整页往上推，推到刚好露出光标那一行，输入框底下那排按钮就压在键盘下面了。`keyboard.js` 跟着 `visualViewport` 走：在输入框、弹出面板、门口（`.kfs-composer`、`.kfs-sheet`、`data-kfs-kbfit`）里打字时，把外壳的 `top` 和 `height` 设成可视区的（`--kfs-kb-top`、`--kfs-kb-h`），输入框整块贴在键盘上面，顶栏留在最上面，底下横条不再让位。日记那种整页滚的地方不管，让 iOS 自己推。

她的手机上，键盘（连同上面那条“上一项、下一项、完成”）顶在屏幕 447 那儿，iOS 把整页推了 344。从截图推算，WebKit 给的可视区这时是对的，不用再补那 59；要是真机上输入框和键盘之间空出一截、或者被压住一截，就是这里要补。`tests/fullscreen.py` 用假的可视区模拟这一下。
